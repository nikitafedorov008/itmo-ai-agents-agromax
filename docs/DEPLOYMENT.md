# Облачный AGROMAX

## Размещение

Render Free запускает Node API и собранный React по одному HTTPS-адресу. Flutter использует тот же API. PostgreSQL, Auth и закрытый Storage находятся в отдельном Supabase Free проекте. Сервер не хранит фотографии на своём диске.

Render останавливает бесплатный сервис после 15 минут простоя; первый запрос может ждать запуска около минуты. Мобильный клиент допускает холодный старт. Это не гарантированная круглосуточная доступность: у Supabase Free также есть политика паузы неактивных проектов. В конфигурации выбраны только Free-планы, платные дополнения не включены. API моделей оплачиваются отдельно их владельцем.

## Воспроизведение

1. Создать новый Supabase Free проект, сохранив старые проекты.
2. Применить миграции из `supabase/migrations`, затем `supabase/seed.sql` и `supabase/cloud-setup.sql`. Не применять начальную миграцию повторно к существующей базе.
3. Включить anonymous sign-ins для изолированного демо. Обычная регистрация сохраняет подтверждение email по настройкам Supabase.
4. Создать сервис по `render.yaml` из корня публичной монорепы. Все секреты вводить только в закрытые Environment Variables Render: URL/anon/service-role Supabase и ключи DeepSeek/MiMo. Не переносить локальный service-role ключ в облако: нужен ключ нового проекта.
5. Проверить `/api/health`, веб, анонимное демо, закрытое фото, подтверждение и задачу. `RENDER_EXTERNAL_URL` автоматически задаёт точный CORS origin; API по неизвестным путям возвращает JSON 404, не HTML приложения.
6. После проверки запустить `node tools/configure-cloud.mjs https://<service>.onrender.com`, пересобрать мобильное приложение. Конфигурация содержит только публичный URL, без ключей.

```sh
cd apps/mobile
flutter run --dart-define-from-file=config/cloud.json
# Явное локальное окружение:
flutter run --dart-define-from-file=config/local.json
```

Для физического iPhone нужен подписанный Xcode build или TestFlight/Apple Developer; публикация сайта не устанавливает приложение на телефон автоматически. Android APK требует Android SDK и release signing. Локальные синтетические пользователи и фото не переносятся в новую базу: облако начинает с отдельного набора данных. Для общей истории на вебе и телефоне необходимо войти в один обычный аккаунт; кнопка демо на каждом устройстве намеренно создаёт разные хозяйства.

## Регистрация по email

Site URL в Supabase указывает на публичный Render origin. Подтверждение email сохранено. Встроенный почтовый сервис Supabase отправляет письма только участникам организации; для самостоятельной регистрации произвольных пользователей нужен отдельный SMTP-провайдер ([официальные ограничения](https://supabase.com/docs/guides/auth/auth-smtp)). SMTP пока не подключён. Демо и вход в уже подтверждённый аккаунт работают; нативный тест использовал подтверждённый синтетический аккаунт.

## Уведомления и лимиты

`pg_cron` запускает `run_scheduler` раз в пять минут внутри Supabase; он не будит Render и не вызывает модели. Уникальные ключи сохраняют защиту от одинаковых уведомлений.

Скрипт `cloud-setup.sql` устанавливает общий предел **50 запусков агента в сутки UTC** на все хозяйства. База атомарно резервирует запуск до обращения к провайдеру; повторы завершённых операций возвращают прежний результат даже при исчерпанном лимите. Ошибочные попытки также учитываются консервативно. Предел ограничивает число запусков, а не устанавливает точный денежный бюджет. Существующие лимиты 12/120 запросов в час для демо/обычного хозяйства сохранены. Изменение общего предела доступно только администратору базы/серверу.

## Откат

В Render можно развернуть предыдущий успешный commit. Данные остаются в Supabase. Миграции не откатываются удалением таблиц; предыдущий код совместим с дополнительной таблицей лимита. Полностью отключить модели можно удалением их ключей из Render Environment — поля, фотографии и задачи продолжат работать.

## Проверено 23 октября 2026

Публичный веб и API: https://agromax-itmo.onrender.com . Render Free, Supabase Free; старые проекты и домашки сохранены.

Облачные проверки: 10 сценариев интеграции и 9 проверок защиты прошли. DeepSeek (`deepseek-flash`) и MiMo (`mimo-v2.6-flash`) вернули HTTP 200 с вызовами истории/источников; MiMo также запросил погоду. Это фактически доступные API-модели на момент проверки.

На iPhone 17 Pro Simulator (iOS 26.4) прошёл нативный интеграционный тест обычного аккаунта: вход через облачный API, сохранение фото в документы приложения, отправка очереди, чтение закрытого фото, повтор без дублей и повторное открытие SQLite. Ту же запись и фотографию затем проверили во встроенном браузере на публичном вебе. Тестовая фотография — синтетический PNG; камера физического телефона этим тестом не проверялась.

Обычная iOS-сборка пересобрана с облачным origin по умолчанию. На физический телефон приложение ещё не установлено; Android в этой среде не проверен (нет SDK). Облачные тесты используют отдельный подтверждённый синтетический аккаунт; проверка email для обычных регистраций сохранена.

Cron `agromax-notifications` активен, расписание `*/5 * * * *`; фактический автоматический запуск 2026-10-23 05:00 UTC завершился со статусом `succeeded`. Лимит — 50 запусков агента в сутки UTC.

Секреты находятся только в закрытых переменных Render и игнорируемой локальной конфигурации. В мобильной и веб-сборках их нет. Локальные доказательства и учётные данные теста сохранены в игнорируемой `.data/cloud/` и не публикуются.
