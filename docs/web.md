# AGROMAX web

React / TypeScript / Vite application, `@agromax/web`. Start API on `http://localhost:8787`, then run `npm run dev:web` from the repository root. Vite listens on port 5173. `VITE_API_ORIGIN` may override the API origin at build time. Build with `npm run build -w @agromax/web`; typecheck with `npm run typecheck -w @agromax/web`.

Chief users can add a real field from the empty state or fields sidebar. Name, crop, area and center coordinates are required; polygon entry is optional. Point-only records are labeled as having no contour and rendered as map markers. Field creation requires explicit confirmation and uses an idempotent operation ID.

The UI uses shared `@agromax/contracts` types and `ApiClient`. No mock data or AI fallback is provided. The demo button requests a separate demo farm from the real API. Synthetic demo boundaries are explicitly marked on the map. Leaflet renders OpenStreetMap tiles; the field list provides keyboard-accessible field selection independently of map controls. External tiles and Google Fonts require network access; system fonts remain available.

Session tokens live in `sessionStorage` (tab lifetime), never in URLs, logs, or permanent localStorage. Logout unmounts the workspace and aborts active bootstrap, weather, chat and photo requests; bootstrap polling stops. Successful mutations reload server state. Private photos are fetched with the session bearer token, displayed using temporary object URLs and revoked on unmount.

Identical mutation retries reuse operation IDs in sessionStorage. Observation save creates a draft. Approval and optional task creation require a separate explicit checkbox and commit to the API together. Task completion requires a written outcome and explicit confirmation. Repeat inspection creates a new observation linked to the original. The app exposes persisted conversations, sources, artifacts, tasks, notifications and weather from the API. Unconfigured model or weather/API failures stay visible; nothing fabricates a response.

Desktop layout shows fields/map, assistant and context side by side. Mobile tabs switch these panels. Forms use native required validation, visible labels, keyboard focus states, loading and error states. All dates use Russian locale. Parent integration verification should exercise the rendered UI through Codex In-app Browser.

## Observation workbench

The main desktop view now pairs a real OSM field map with an observation workbench. Mobile keeps the same observation flow with field/material navigation. The hero shows the latest selected observation's authenticated private photo and actual note. Without a photo it shows `public/wheat-leaf.png`, explicitly labeled “Иллюстрация культуры”; this is never presented as a diagnosis or captured field image. Map observation markers are created only for saved coordinates; marker clicks select the corresponding observation. Field and observation labels use text nodes, never user-supplied HTML.

`Chat.tsx` owns the real conversation, provider and request lifecycle. `Workbench.tsx` presents actual reply artifacts; `workbenchLogic.ts` isolates request context and evidence rules. Clarification options and custom answers exist only when returned in `artifact.question`. Every answer calls the existing chat API with the current conversation, field, observation and provider; identical retries retain the operation ID. The latest persisted conversation is available through a native discussion dialog. Provider selection is also exposed directly in the workbench, and unconfigured providers are labeled. Historical artifacts without optional workbench metadata remain readable.

Only tool names in `reply.tools` produce completed evidence labels. While a request runs, a neutral spinner replaces completed labels. Source disclosure renders the actual reply sources, including excerpts and versions; no synthetic citations or progress are generated. Action enums map to field history, weather, source disclosure, discussion, repeat observation or the existing separate review/approval form. Actions requiring an observation are disabled when none exists. Approval retains version checks, explicit human confirmation and optional linked task creation; task completion still requires its own outcome and confirmation.

Validation: `npm run test -w @agromax/web` covers provider/observation request continuity, current reply context, actual-tool evidence, billable retry decisions and stable photo upload identities. `npm run build -w @agromax/web` includes TypeScript checking. Parent integration performs rendered desktop/mobile QA in Codex In-app Browser and real provider verification.

The field map starts with actual Esri World Imagery public cached tiles, with source attribution retained on the map. The accessible “Схема / Спутник” switch selects OpenStreetMap or imagery. If imagery tiles fail, the map automatically switches to OpenStreetMap and explains the fallback. A failed schema layer also displays an explicit notice while local field geometry and observation markers remain available. Imagery is a basemap only and does not imply NDVI, fresh capture dates or crop diagnosis.
