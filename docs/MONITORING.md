# Мониторинг облачного агента

`GET /api/metrics/demo` возвращает только телеметрию явно разрешённых синтетических демо-хозяйств. Обычные хозяйства по умолчанию не включаются. Нет текстов диалогов, заметок, email, координат, фото, UUID хозяйств или токенов. `run-…` — короткая диагностическая ссылка, не пользовательский идентификатор.

Миграция `202610230003_monitoring.sql` создаёт закрытую схему `monitoring`, allowlist `demo_farms`, триггер времени завершения и сервисную RPC `demo_monitoring_snapshot`. Выполнить миграцию однократно администратором. Затем явным отдельным SQL добавить только согласованное синтетическое хозяйство в allowlist. В публичном репозитории его идентификатора нет.

RPC доступна только service_role. Endpoint выдаёт заранее ограниченный результат, не принимает farm ID или SQL. DataLens API Connector делает только GET к HTTPS-хосту Render, без ключей Supabase. Это отдельный дашборд; старая домашка и n8n не меняются.

## Определения

Окно запусков — последние 30 суток UTC. Наблюдения и задачи — текущее состояние выбранных демо-хозяйств, не когорта за 30 дней. Доля успеха = completed / (completed + failed); running показываются отдельно. Ошибка = failed / завершённые. Уточнения и ответы с источниками = соответствующие completed / completed. Это наличие ссылки, не оценка её качества. Tools — уникальные использованные типы инструментов в результате; это не число вызовов.

Средняя/p95 задержка — завершённые successful запуски с известным временем. Новые интервалы: `finished_at - created_at`, включая обработку сервера и сохранение; это не клиентский end-to-end и не только время LLM. Для старых completed использован reply.createdAt и стоит `legacy_reply_timestamp`; старые failed без timestamp не включаются в длительности. Нулевые знаменатели отображаются «н/д».

Последние 200 событий — диагностический журнал; сводка и почасовая серия рассчитываются по всем запускам окна. Ошибки хранят только код; прерванные running закрываются фоновым scheduler после пяти минут. Выборка учебная, без агрономической оценки и без заявлений о промышленной надёжности.

DataLens автоматически запрашивает HTTPS endpoint; фактический цикл и доказательства обновления фиксируются после проверки. Бесплатный Render может спать: первый запрос тогда требует прогрева.
