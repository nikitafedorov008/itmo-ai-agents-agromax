# AGROMAX

Веб и мобильное рабочее пространство агронома: наблюдение → уточнение → подтверждение → повторный осмотр → история поля.

Новая учебная версия. Старые сдачи и интеграции в `Agents/AGROMAX-*` не используются как рабочая база и не изменяются.

## Облачная версия

[Открыть AGROMAX](https://agromax-itmo.onrender.com) — веб и API на Render Free, данные в Supabase Free. Первый запуск после простоя может занять около минуты. Для знакомства нажмите «Открыть демохозяйство». Для общей истории на вебе и телефоне нужен один обычный аккаунт. Мобильная конфигурация по умолчанию уже указывает на этот сервер. [Развёртывание и проверки](docs/DEPLOYMENT.md).

## Рабочее пространство

Осмотр объединяет фотографию и заметку, спутниковую карту, этапы разбора и карточку ответа ИИ. Помощник возвращает уточняющие вопросы с вариантами и свободным ответом; выбор продолжает тот же диалог. История, погода и источники открываются из карточки. Подтверждение наблюдения и создание задачи остаются отдельным действием агронома.

На iOS используются Cupertino-навигация, вкладки, поля ввода, окна выбора и подтверждения; Android сохраняет Material 3. Карта переключается между спутниковой подложкой Esri и схемой OSM. Сетевые слои требуют подключения; офлайн-черновики и очередь остаются доступны.

## Структура

- `apps/web` — React + TypeScript + Vite.
- `apps/mobile` — Flutter, Riverpod, SQLite, камера и GPS.
- `apps/api` — Hono, Supabase и агент с DeepSeek/MiMo.
- `packages/contracts` — типы, OpenAPI, генерируемые маршруты TypeScript/Dart.
- `supabase` — локальная конфигурация и миграции с RLS.

## Локальный запуск

Нужны Node.js 22+, Docker, Flutter и нативные SDK для нужной платформы. Пакеты фиксируются lock-файлами. Docker должен быть запущен.

```sh
npm ci
npm run setup:local
# Добавить DEEPSEEK_API_KEY и MIMO_API_KEY в apps/api/.env.
# Файл уже содержит автоматически подставленные локальные настройки Supabase.
npm run dev
```

Веб: http://localhost:5173, API: http://localhost:8787. API не выдаёт ключи моделей клиентам. Вход «Демо» создаёт отдельное хозяйство с синтетическими полями.

```sh
cd apps/mobile
flutter pub get
flutter run --dart-define=API_BASE_URL=http://localhost:8787
# Для Android Emulator вместо localhost: http://10.0.2.2:8787
```

Для облачного приложения используйте `flutter run --dart-define-from-file=config/cloud.json` из `apps/mobile`. Оно не зависит от работающего компьютера. Для локального API на физическом телефоне нужен адрес компьютера в той же сети.

## Проверки

```sh
npm run contracts:generate
npm run typecheck
npm test
npm run build
# При работающем локальном API; реальные платные обращения к обоим провайдерам:
npm run check:workbench
cd apps/mobile
flutter analyze
flutter test
```

Сценарии проверки и фактические результаты — `docs/VERIFICATION.md`. Успешная сборка не означает проверку на телефоне. Доступность провайдеров проверяется отдельно с реальными ключами.

## Ограничения

LiteRT и собственная модель компьютерного зрения — следующий этап. Фото сохраняется как материал наблюдения; диагноз и лечебные назначения не считаются подтверждёнными результатами. Метрики демо не доказывают точность модели или экономию реального хозяйства.
